# Livelink 实现计划

## 1. 当前执行目标

在 48 小时内完成一个可演示的 AI 数字分身社交名片 MVP。

核心 Demo 闭环：

```text
用户在 H5 创建 AI 人物卡片
  → 编辑发布
  → 生成 H5 公开页二维码
  → 他人扫码查看
  → 一键请求连接
  → 基于个人信息、地址/场景信息做基础推荐
  → 卡片主人接受
  → 展示连接记录
```

## 2. 优先级原则

48 小时内，任何功能都按以下原则取舍：

1. 是否服务主 Demo 闭环。
2. 是否能让评委更快理解产品价值。
3. 是否能提升卡片分享欲。
4. 是否能降低现场演示风险。

如果答案是否，就延后。

## 3. 48 小时执行排期

- 确定页面路由。

- API health check 可用。

- AI 结果编辑页。
- 公开卡片页。
- 探索 / 推荐页。
- 连接列表页。
- Mock 数据。

验收：

### 8-16 小时：AI 生成

- 实现后端生成 API。

验收：

### 16-24 小时：持久化与公开页

- 接入 SQLite / Prisma。
- 保存用户和卡片。
- 发布卡片。
- slug 公开访问。

验收：

### 24-32 小时：连接请求

任务：

- 公开卡片发起连接。
- 发送默认破冰语。
- 收件箱查看请求。

- 展示连接记录。

验收：

- 扫码 → 请求连接 → 推荐 → 接受 → 连接记录闭环跑通。

### 32-38 小时：体验加分

### 38-44 小时：测试修复

任务：

- 真机扫码测试。

### 44-48 小时：路演准备

- 准备备用链接和备用数据。

## 5. Demo 主路径

### 5.1 创建卡片

1. 用户打开首页。
2. 点击“创建我的 AI 分身名片”。
3. 填写昵称、身份、城市、经历、兴趣、希望认识的人。
4. 点击“AI 生成卡片”。
5. 系统生成一句话介绍、简介、标签、适合聊什么、破冰语。
6. 用户编辑并发布。
7. 系统展示公开卡片和 H5 二维码。
8. 系统根据城市、场景、标签生成基础推荐。

### 5.2 扫码连接

1. 演示者展示 H5 二维码。
2. 另一台手机扫码打开 H5 公开卡片。
3. 访问者查看人物介绍、标签、适合聊什么。
4. 访问者点击“想认识 TA”。
5. 系统展示默认破冰语。
6. 访问者发送连接请求。
7. 卡片主人查看请求。
8. 卡片主人接受。
9. 连接列表展示连接记录。
10. 探索页展示同场景或兴趣匹配的推荐用户。

## 7. 路演脚本

### 7.1 开场

现实社交中，我们经常交换微信，但对方很难真正理解我是谁。Livelink 希望让每个人都有一张会自我介绍的 AI 数字分身名片。

### 7.2 演示创建

我只需要输入几段基础信息，比如我是谁、做过什么、关注什么、希望认识谁。AI 会自动帮我生成一张适合社交展示的人物卡片。

### 7.3 演示卡片

这张卡片不是简历，而是一张能帮助别人快速理解我的社交名片。别人可以看到我的标签、经历、适合聊什么，以及我希望认识什么样的人。

### 7.4 演示扫码

在线下活动中，我只需要展示二维码。对方扫码后，10 秒内就能知道我是谁，并且可以一键请求连接。后续迁移到小程序后，这个入口会升级为小程序码。

### 7.5 演示连接

系统会自动生成一句破冰语，降低社交开口成本。连接建立后，系统会记录我们是在什么时候、通过什么方式认识的。

### 7.6 未来展望

Livelink 会基于用户的人物卡片、地址/场景信息和连接行为，推荐更值得认识的人，并逐步形成现实社交中的数字身份和关系网络。

## 8. 路演 PPT 建议

### 第 1 页：问题

- 现实社交中，交换联系方式容易，真正理解一个人很难。
- 普通名片太单薄，简历太正式，社交主页太分散。

### 第 2 页：解决方案

- Livelink：AI 数字分身社交名片。
- 3 分钟创建，10 秒理解，一键连接。

### 第 3 页：产品 Demo

- 创建 AI 卡片。
- 扫码查看。
- 请求连接。
- 连接记录。

### 第 4 页：技术亮点

- AI 信息提炼。
- 结构化人物卡片。
- 破冰语生成。
- H5 二维码现实社交入口，后续可升级小程序码。

### 第 5 页：未来空间

- 探索模式。
- AI 推荐用户。
- 地址 / 场景推荐。
- 社交图谱。
- 活动场景商业化。

## 9. 备用方案

必须准备：

- 如果 AI API 失败，使用预置 Mock 结果。
- 如果二维码扫码失败，直接打开 H5 公开链接或使用本地 Demo 数据。
- 如果数据库异常，使用本地 Mock 数据演示。
- 如果登录失败，使用 Demo 用户绕过。
