# Livelink 项目方案

## 1. 项目定位

Livelink 是一个面向现实社交场景的 AI 数字分身名片产品。用户可以快速生成一张可分享的人物卡片，别人通过扫码快速了解用户，并一键发起连接。

## 2. 一句话描述

Livelink 是一张会自我介绍的 AI 数字分身名片，让用户 3 分钟生成个人卡片，别人扫码 10 秒了解你，并一键建立连接。

## 3. 当前阶段结论

当前项目处于 48 小时黑客松阶段，执行策略是：

```text
当前阶段：先用 H5 开发完整 Demo，跑通核心闭环
架构原则：按后续迁移小程序的方式设计前后端边界
长期方向：沉淀个人身份知识库、推荐系统、社交图谱和活动场景
```

当前最高优先级不是一次性完成完整架构，而是先完成一个稳定、好看、可演示的轻量闭环，同时保留个人信息、地址/场景信息和推荐能力的主线：

```text
创建 AI 人物卡片 → 记录个人信息和地址/场景信息 → 编辑发布 → 生成二维码 → 扫码访问 → 请求连接 → 基础推荐 → 记录连接
```

## 4. 产品价值

### 4.1 对卡片创建者

- 降低自我介绍成本。
- 用更好看的方式展示自己。
- 让别人更快理解“我是谁”。
- 提升线下社交中的表达效率。

### 4.2 对扫码访问者

- 快速了解对方身份、经历、兴趣和可聊话题。
- 降低破冰成本。
- 一键发起连接请求。

### 4.3 对平台

- 沉淀用户数字身份。
- 沉淀用户连接关系。
- 基于人物卡片、地址/场景信息和连接行为做推荐。

## 5. 目标用户

长期面向泛社交用户，早期优先服务：

- 年轻职场人
- 学生
- 创作者
- 创业者 / 独立开发者
- 线下活动参与者

黑客松 Demo 聚焦：

- 黑客松参与者
- 创业活动参与者
- AI 产品 / 独立开发爱好者

## 6. 核心场景

### 6.1 线下初见

活动、展会、咖啡聊天、朋友聚会中，用户展示二维码，别人扫码快速了解用户。

### 6.2 社交破冰

访问者通过人物卡片看到用户的简介、标签、经历、兴趣和适合聊的话题，从而更自然地发起交流。

### 6.3 连接沉淀

扫码访问者可以一键请求连接，系统记录连接时间、来源和留言，帮助用户回顾自己认识的人。

### 6.4 推荐

系统需要根据人物卡片、兴趣、经历、连接行为和活动场景推荐值得认识的人。当前阶段先做轻量规则 / Mock 推荐，后续升级为完整推荐系统。

### 6.5 地址 / 场景感知

用户打开可见状态或在某个线下场景中使用产品时，系统需要记录轻量地址或场景信息，用于发现和推荐。

当前阶段先支持：

- 用户手动填写城市。
- 用户手动选择当前场景，例如黑客松、活动、校园、咖啡聊天。
- 用户可选填写地点名称，例如某活动名、某场馆、某学校。

后续阶段再接入：

- 小程序定位授权。
- 活动签到位置。
- 附近用户发现。
- 基于地理位置和场景的推荐。

## 7. 产品主闭环

1. 用户进入产品。
2. 用户创建 AI 人物卡片。
3. 用户输入基础信息。
4. AI 生成人物简介、标签、经历总结和破冰话题。
5. 用户编辑确认并发布卡片。
6. 系统生成公开链接和二维码。
7. 其他人扫码访问卡片。
8. 访问者一键请求连接。
9. 卡片主人接受或忽略请求。
10. 双方形成连接记录。

## 8. 当前 MVP 范围

### 8.1 必须完成

| 模块 | 功能 | 说明 |
| --- | --- | --- |
| 用户身份 | Demo 登录 / 模拟用户 | 使用 Demo 登录承载，保留用户身份模型 |
| 个人信息 | 基础资料保存 | 昵称、身份、城市、经历、兴趣、希望认识的人 |
| 地址/场景 | 轻量场景信息 | 城市、当前活动/地点名称、使用场景 |
| AI 生成 | 生成人物卡片 | headline、bio、tags、经历总结、话题、破冰语 |
| 编辑发布 | 用户可编辑并发布 | AI 内容不能直接强制发布 |
| 公开卡片 | H5 公开卡片页 | 适合手机扫码，后续小程序复用数据 |
| 二维码 | 生成 H5 公开页二维码 | 现场扫码演示，后续替换/补充小程序码 |
| 请求连接 | 一键请求连接 | 访问者发送留言 |
| 连接记录 | 查看连接状态 | 展示连接时间、留言、来源 |
| 基础推荐 | 轻量推荐用户 | 基于标签、城市、场景、希望认识的人做 Mock/规则推荐 |

### 8.2 分阶段增强

- 探索页：当前用 Mock/规则推荐，后续接真实推荐。
- AI 推荐理由：当前可基于标签和场景生成一句理由，后续接完整推荐系统。
- 分享海报：当前可后置，后续提升传播。
- 访问次数统计：当前可记录基础访问，后续做数据分析。
- Demo 用户一键生成：当前用于演示，后续替换成真实用户。
- 卡片视觉模板切换：当前先做默认模板，后续扩展多模板。

### 8.3 当前阶段降级实现

以下能力属于系统目标，但黑客松阶段采用轻量实现：

| 能力 | 当前实现 | 后续实现 |
| --- | --- | --- |
| 登录身份 | Demo 用户 / 简化身份 | 微信授权登录 |
| 小程序主体验 | H5 先行，结构可迁移 | 正式小程序 + H5 公开页 |
| 小红书 / GitHub 导入 | 手动粘贴摘要 | 平台链接解析和提炼 |
| 简历解析 | 手动输入经历 | 文件上传和文本解析 |
| 推荐系统 | Mock/规则推荐 | 标签、意图、位置、场景、连接行为综合推荐 |
| 个人知识库 | 卡片字段 + 原始输入 | source、fact、trait、version 完整结构 |
| 社交图谱 | 连接记录 | 共同好友、关系路径、图谱展示 |
| 虚拟世界 | 探索列表 | 雷达、地图、空间化发现 |
| 商业化 | 路演中描述方向 | 活动方、模板、数据分析等增值 |

## 10. AI 人物卡片内容

人物卡片建议包含：

- 头像 / 昵称 / 城市
- 当前场景 / 地点名称
- 一句话介绍
- AI 人物标签
- 人物简介
- 经历总结
- 兴趣领域
- 适合聊什么
- 希望认识什么人
- 破冰话题
- 请求连接按钮
- 分享二维码
- 推荐匹配信息

## 11. 视觉体验原则

人物卡片是产品核心，需要优先做好。

- 第一眼好看，适合分享。
- 信息层级清晰，10 秒内理解这个人。
- 标签要明显。
- “适合聊什么”要突出，帮助破冰。
- 请求连接按钮要非常明确。
- 移动端优先。

## 12. 后续演进路线

### 阶段 1：H5 黑客松 Demo

目标：

- 跑通核心闭环。
- 完成现场演示。
- 验证用户是否愿意创建和分享 AI 人物卡片。

范围：

- H5 创建 / 编辑卡片。
- AI 生成。
- H5 公开页二维码。
- 扫码访问。
- 请求连接。
- 基础推荐。
- 连接记录。

### 阶段 2：小程序 MVP 迁移

目标：

- 进入微信生态。
- 复用 H5 阶段的数据模型、API 和 AI 逻辑。
- 提升扫码、登录、分享和推荐体验。

范围：

- 微信授权登录。
- 小程序创建 / 编辑卡片。
- 小程序码参数化。
- 微信分享卡片。
- 位置授权和场景记录。
- H5 公开页继续保留。
- 后端 API 独立化。

### 阶段 3：资料增强

目标：

- 让 AI 更懂用户。

范围：

- 简历上传。
- GitHub 链接导入。
- 小红书 / 作品集链接导入。
- 原始资料保存。
- 结构化事实抽取。
- 卡片版本管理。

### 阶段 4：探索与推荐

目标：

- 从名片工具变成社交产品。

范围：

- 开启可见。
- 可见用户列表。
- 城市 / 地址 / 场景推荐。
- 标签和兴趣规则推荐。
- 希望认识的人匹配。
- AI 推荐理由。
- 推荐破冰语。
- 推荐反馈。

### 阶段 5：个人身份知识库

目标：

- 沉淀长期数字身份。

原则：

- 原始资料永久保留。
- 事实和表达分离。
- 每个结论有来源。
- 用户拥有最终控制权。

### 阶段 6：社交图谱与空间化社交

目标：

- 形成长期社交关系资产和更沉浸的发现体验。

范围：

- 社交图谱。
- 连接来源分析。
- 活动空间。
- 社交雷达。
- 地图式发现。
- 个人 CRM。

## 13. 风险与应对

### 13.1 48 小时开发风险

| 风险 | 应对 |
| --- | --- |
| 范围过大 | 分层实现：当前轻量推荐和场景信息，后续补完整系统 |
| AI 不稳定 | Mock 兜底 |
| 扫码失败 | 准备 H5 公开链接和本地 Demo 数据备用 |
| 数据库异常 | 准备演示数据 |
| 页面不好看 | 优先优化 H5 公开卡片页 |
| 时间不够 | 先完成静态 Mock，再接真实数据 |

### 13.2 产品风险

| 风险 | 应对 |
| --- | --- |
| 用户不愿上传资料 | 支持极简输入，结果吸引补充 |
| AI 生成不像用户 | 支持编辑、重生成、风格调整 |
| 用户没有分享动机 | 卡片视觉要好，提供二维码和反馈 |
| 泛社交骚扰 | 默认不公开联系方式，连接需请求 |
| 冷启动没人可推荐 | 先用 Demo 用户、同场景用户和规则推荐 |
